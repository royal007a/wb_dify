# 有界标量分支聚合

对应 WORKFLOW-AGGREGATION-001，任务结果以Harness为准；本文是实现契约，不是部署证据。

- DSL新节点 `AGGREGATOR`，仅接受 `candidates`、`outputVariable`、`__ui`；不得把这一白名单套到历史节点。
- 候选2–16个严格 `node.variable`，每个生产者最多出现一次，必须是严格祖先且变量在源码规则中有声明。不能使用KNOWLEDGE列表；嵌套聚合也按同样标量约束逐层校验。
- 对每个聚合节点，在DAG拓扑序上传播路径候选计数集合，截断到0/1/2，入集合必须恰好 `{1}`。因此同时有0和1的路径会拒绝，不能只看max。条件默认边始终参与结构检查，重复前驱只算一次。
- 下游模板引用聚合的输出时仍要求聚合节点必经；其他节点引用分支变量仍然拒绝。不是第一个非空值策略，不是并行barrier。
- 运行时按键是否存在而非布尔真值选择。恰一个非null标量才写新输出；空文本、0、false、BigDecimal保留；不解析候选内容里的模板。非法上下文的0/多个/null/列表防御只在节点单测中构造，不称为HTTP可达故障。
- 保留50步、取消和deadline；没有新的外部调用，没有迁移，没有新增依赖。END仍是执行结果，不是来源或语义真实性保证。

## 兼容与回退

只扩展节点类型集合、新节点校验和执行分支，旧config中的额外属性不变。旧发布JSON原文checksum不重算；回归覆盖无聚合图字节一致、历史扩展字段通过发布/执行/能力目录，以及新图两条分支的版本固定。

旧二进制不能识别新节点，现有目录逻辑会过滤非法发布版本；不能承诺部署后直接回旧jar仍能运行新图。发布与回滚另立任务，不在本地门禁通过后自动发布。

## 证据分层

单元测试：路径0/1和1/2、多候选、非法引用/配置、嵌套汇合、START候选拒绝、类型和非法上下文、旧图序列化。

H2/MockMvc集成：持久发布、两分支节点轨迹、草稿更新后原版本稳定、能力目录仍显示旧扩展字段的图。它不是实际网络或PG兼容证明；完整backend scope中的既有PG回归另有摘要。

浏览器：管理台新增节点、默认配置和编辑后请求序列化使用受控HTTP打桩；不声称真实后端保存/发布或线上浏览器验收。

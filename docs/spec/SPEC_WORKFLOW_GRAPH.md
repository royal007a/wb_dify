# Workflow 图和条件语法

任务 SPEC-WORKFLOW-GRAPH-002，范围为确定性 JSON DSL。保存、校验、发布、Agent 绑定/发布以及执行前共用校验器；不改变已发布 DSL/checksum，不增加迁移。

## 路径长度

结构约束继续要求单 START、至少一 END、可达无环、非条件单出边、条件默认分支、严格必经上游变量。按拓扑序计算每个节点的最长前驱路径：START 长度 1，当前长度为最长前驱长度加 1。最长结构路径最多 **50 步（含 START 和 END）**，运行兜底使用同一常量。

不是全图节点总数限制：97 节点的双分支图可以通过，只要每条路径不超过 50。校验不会求解输入和条件的可满足性；即使某条边因常量条件永远不走，它也计入结构路径。超限图在写入前返回 HTTP400，旧非法版本执行也拒绝。

## 条件语法

支持三类：`true/false`（不区分大小写）；一个完整 `{{node.variable}}`；两个文本操作数之间的单个 `contains`、`==` 或 `!=`。单模板在运行时必须得到 true/false，否则节点失败；不保证任意用户输入是布尔值。

- `contains` 两边须有空白；`==` / `!=` 不要求空格。比较大小写敏感，不做数值或真假值隐式转换。
- 简单文本/短语及模板可不加引号；包含操作符、引号或 `= ! < > & | ( )` 的字面量必须用单引号或双引号包围。引号内支持 JSON 字符串转义（另允许单引号字符串）。
- 例如 `{{start.userMessage}} == 'a contains b'`、`{{start.userMessage}} contains "型号 == A"`。不支持多操作符、布尔组合、函数或任意脚本；缺操作数、裸 hello、不闭合引号、尾随语法在保存/发布前拒绝。
- 先解析表达式、解码字面量，再检查解码后所有模板的必经上游；最后才进行一次插值和比较。输入中的 contains、引号、占位符不会再被当作语法求值。
- `{{` / `}}` 在配置中保留给模板，没有字面量转义机制；引号并不禁用模板插值。新建表单对关键词做 JSON.stringify 转义；直接编辑画布表达式仍须遵守此语法。

旧的歧义表达式（例如裸右值里又包含 contains/==）可能被拒绝，需要编辑草稿、重新发布 Workflow，再重新发布绑定的 Agent、新建会话。原版本不自动改写。原本合法的简单 contains/==/!=、布尔条件及纯模板图保持兼容。

## 错误分类与验收

图/表达式校验抛出公开 WorkflowDefinitionException：管理和直接执行 HTTP400；既有 Chat 遇到旧非法定义落为 FAILED / WORKFLOW_ERROR，不调用模型、不执行节点、不写助手回复。不是把所有数据库、checksum 或配置加载错误统一归类（其余路径由 Workflow 恢复任务承接）。

单测验证 50/51 边界、宽图、环、真正自引用、多 START、含操作符/转义的字面量、动态布尔、解码后变量。HTTP 测试验证保存/更新/校验/发布/执行、旧版本绑定拒绝与 Chat 终态。前端类型检查/构建不等于浏览器验收；H2 测试不等于 PostgreSQL 并发测试。

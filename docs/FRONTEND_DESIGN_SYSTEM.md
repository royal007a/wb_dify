# Hify 前端设计系统与公共组件

基线日期：2026-09-13。目标是面向开发者和技术管理者的浅色管理后台：高密度信息保持可读，深色侧边栏和蓝紫—薄荷绿点缀提供品牌与科技感，不引入装饰性噪声。

## 0. 课程阅读结论

这篇材料的重点不是“让 AI 写 CSS”，而是一套适用于非前端主业开发者的 UI 协作方法：

1. **提示词逐层收敛**：产品是什么 → 用户是谁 → 视觉方向 → 色调细节 → 参考锚点。上下文越完整，AI 越少依靠猜测。
2. **先系统、后页面**：先固定颜色、间距、圆角、阴影和动效，再改导航与页面；否则每个页面会形成独立风格。
3. **先公共交互、后业务**：表格、分页、弹窗、确认、请求三态和通知先封装，业务页面只承担字段、规则和 API 编排。
4. **AI 出初稿，人做判断**：生成代码可以批量完成，但状态语义、信息层级、对比度、密度和响应式取舍必须由实际界面判断。
5. **反馈必须可执行**：不用“更好看”这类抽象反馈，而使用“间距 24 改 16”“禁用用 info 而非 danger”“弹窗改 520px”这类可验证指令。
6. **验收包含行为**：能构建不等于完成；还要验证弹窗打开、校验报错、确认删除、列表刷新和窄屏布局。

Hify 的实现采用了这套顺序，但没有机械照抄：保留真实健康检查与既有 Query Loop 页面；Provider 数据暂用 mock 作为组件夹具，并在文档中明确标识，避免把视觉完成误报成业务 CRUD 已联通。

## 1. 视觉令牌

权威实现位于 `frontend/src/styles/tokens.css`：

- 主色：蓝紫 `#6240e8`，提供 50–900 色阶；关键操作使用蓝紫到深青的品牌渐变，保证白字对比度。
- 辅色：薄荷绿 `#14b8a6`，用于连接状态和数据提示，不与主操作竞争。
- 背景：白色内容面、`#f5f7fb` 页面底、`#eef1f7` 次级填充、`#10111a` 深色导航。
- 文字：`#171925` 主文字、`#5b6474` 次文字、`#8992a3` 辅助文字；正文不使用低对比度浅灰。
- 圆角：4/7/10/14/18px；表格与表单保持克制，卡片和弹窗使用 14px。
- 阴影：xs/sm/md 三档，全部为低透明冷灰阴影；焦点环使用主色 16% 透明度。
- 动效：140/220/340ms，使用标准和强调两条缓动；系统开启 reduced motion 时自动降为 0ms。

CSS 变量同时桥接 Element Plus 的 primary、success、danger、文字、边框与圆角变量，避免组件库与业务页面出现两套色彩语言。

## 2. 布局规则

- 侧边栏 232px，折叠后 76px；小于 1200px 自动折叠，只保留图标。
- 顶栏 64px，包含当前路径面包屑和用户占位信息。
- 页面边距 24px、卡片内边距 20px、标题区与内容间距 16px。
- 内容区使用浅灰背景，表格/表单位于白色卡片；选中菜单以 3px 渐变竖线和半透明底强调。
- 小于 1200px 的 Provider 表格移除 Base URL 与创建时间列；小屏弹窗最大宽度为视口减 32px。

## 3. 公共组件契约

| 组件 | 责任 | 关键接口 |
|---|---|---|
| `HifyTable.vue` | 请求、loading、空状态、分页、列/插槽渲染 | `columns`、`api`、`showPagination`、`refresh(resetPage?)` |
| `HifyFormDialog.vue` | v-model、表单校验、提交 loading、关闭重置、新增/编辑初始化 | `title`、`width`、`rules`、`initialValue`、`open(data?)`、`submit(value, done)` |
| `useConfirm.ts` | 确认、执行、成功提示 | `execute(...args)`、`confirming` |
| `useRequest.ts` | data/loading/error/execute 四态 | 泛型 API 入参与返回值 |
| `notify.ts` | 成功、错误、警告提示的时长和关闭行为 | `notifySuccess/Error/Warning` |

Provider 页面使用 5 条 mock 数据作为组件验收夹具；它不宣称 Provider 后端 CRUD 已联通。健康状态仍调用真实 `/api/v1/health`。

## 4. 验收证据

- `npm run typecheck` 通过。
- `npm run build` 通过；既有 Element Plus 整包导致的大 chunk 警告仍是非阻塞技术债。
- 核心对比度抽查：主文字/白底 17.47:1、次文字/白底 5.97:1、侧栏文字/深底 9.97:1、白字/主色 6.14:1，均达到 WCAG AA 正文阈值。
- 1440×900 浏览器截图确认浅色内容、深色侧栏、渐变品牌、状态色和表格密度。
- 1080×800 浏览器截图确认侧栏自动折叠、非关键列移除且表格重新占满内容宽度。
- 浏览器真实交互确认：初始 5 行；新增弹窗可打开；空提交产生 4 条校验错误；删除确认出现；确认后变为 4 行并显示成功提示。

# Dify 官方教程与 Hify 能力差距

这份报告回答三个问题：Dify 教程实际教了什么，Hify 与 hify-cc 哪些能力已经存在，哪些差距值得在本轮实现。结论是先补可靠的工作流数据契约和外部调用，再考虑复用与治理；不能用增加节点名称代替完整运行能力。

阅读日期为 2026-10-04。原版比较基线为 7bfb2b5，CC 为 a7fa403；CC 的后续实现由 mymacclaude 独立负责。原版此前线上部署代码是 42db727，本地语义检索和外部节点不等于已经上线。本文是审计与候选设计，任务及完成状态唯一来源仍为 `harness/tasks.json`。

## 来源范围与版本边界

用户重复给出的核心概念和 New Agent 链接合并阅读；断开的 lesson-02/04/05/07/08/09 链接按官方目录恢复。官方目录列出 lesson-01 至 lesson-10，`lesson-0x` 本次访问失败，不将其算作已阅读的第十一课。

官网、教程、发布文章分别证明产品定位、文档描述的用户流程和发布方声明，不能直接证明本地 Community 镜像具备全部功能。本机此前部署的 Dify 1.17.1 也没有在本轮执行这些完整教程。我们不复制 Dify 源码或假定许可证与普通 Apache 项目完全一致。

### 官网和文档首页

[官网](https://dify.ai/zh)把构建、知识准备、工具集成、发布和监控作为一条产品链路，并区分 Cloud、企业版与社区版。官网的 SSO、SAML、企业审计等表述不能全部归到社区版。对 Hify 的启发是让用户看得懂“从配置到实际使用”的入口，而不是只展示 CRUD 页面。

[文档首页](https://docs.dify.ai/en/home)提供编排、发布、监控、知识、集成和工作区六类入口，同时区分 Cloud 与自托管。它是能力导航，不是性能或可靠性证明。Hify 当前文档和控制台需要按实际用户路径组织，不能让测试清单代替使用手册。

### 核心概念

[Key Concepts](https://docs.dify.ai/en/learn/key-concepts)区分单次 Workflow 和面向每轮会话的 Chatflow；后者有会话变量、LLM 记忆与分段输出。输入和节点输出是不可变数据，环境变量承担配置/秘密分离，DSL 用于导出与迁移。Hify 有不可变发布图和会话版本固定，但只有 `userMessage` 输入，不具备同等的可声明输入表单、会话变量或 DSL 导入导出。版本固定是优势，不意味着 Chatflow 功能齐全。

### 快速入门

[Quick Start](https://docs.dify.ai/en/quick-start)用多平台内容生成展示复合链路：表单与文件输入、参数抽取、条件分支、列表过滤、文件文本提取、多模态 LLM、逐项生成、结构化输出和模板排版。教程从 Cloud 开始，也指向自托管；示例模型和额度不是本项目的默认条件。它说明结构化数据是节点组合的基础。Hify 本轮可优先覆盖文本/数值输入与有界输出；文件、多模态、并行迭代应明确留作后续，不能把一个 LLM 节点叫作“同等快速入门”。

## Workflow 101 逐课总结

### 第一课 工作流和节点

[Lesson 01](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-01)从输入、处理和输出解释工作流，强调每个节点承担明确步骤，模板帮助新用户理解连接关系。Hify 已有同源 DSL 画布、START/END、确定性条件与执行记录；缺口是可直接复用的示例模板及更清晰的输入输出契约。界面能拖动节点不代表支持任意 DAG 并行。

### 第二课 输入与输出

[Lesson 02](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-02)用客户姓名和邮件正文说明命名变量、显示标签、长度限制与输出引用，也介绍手动输入和自动触发两种入口。Hify 的 START 目前只接收单条文本，用户需把不同字段混在 prompt。结构化输入是本轮优先缺口；定时与事件触发没有现成调度可靠性基础，不顺带实现。

### 第三课 模型节点

[Lesson 03](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-03)覆盖模型配置、system/user 消息、变量插入、发布前配置检查与逐节点试运行。Hify 本地外部节点已复用 Provider、冻结模型配置和预算，但未部署，且 HTTP 安全复核尚有 P1。已有 `maxOutputTokens` 并不等于支持所有供应商参数；真实模型和固定假响应须分别证明。

### 第四课 知识检索

[Lesson 04](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-04)把文档分块、索引、Top K 检索和 LLM 上下文串起来，并要求思考知识库没有答案的情况。原版有冻结语料、引用完整性门禁及小型库真实 embedding；语义检索限定 512 chunks/24MiB 精确扫描，不是 ANN。Workflow 的检索输出供后续节点使用，不自动获得 Chat 的来源交付门禁；需要显式标注，不能以 RAG 消除幻觉作保证。

### 第五课 条件与分支汇合

[Lesson 05](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-05)介绍条件分流和 Variable Aggregator，把互斥路径的结果合成统一下游变量。Hify 的条件支持布尔/contains/相等判断，已有两条分支的真实运行证据，但必经上游变量校验不等于拥有“择一结果汇合”节点。候选设计应只汇合已执行分支，不能把未执行节点伪造为成功。

### 第六课 参数抽取与迭代

[Lesson 06](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-06)先把多问题文本抽取为数组，再对每项检索回答，最后汇总。它区分顺序/并行以及失败时终止、继续或移除错误输出。Hify 尚无参数提取和迭代子图；增加时至少要有数组大小、总步骤、总 token/时间、取消传播及每项错误记录。直接在 Java 中无限循环调用模型不能视为等价实现。

### 第七课 外部工具

[Lesson 07](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-07)在知识不足时分支到外部搜索，强调工具安装、凭据配置与结果汇合。教程用 LLM 输出固定语句判断“未找到”，这是示例策略，不是本项目可直接采纳的强验证门禁。Hify 本地有精确授权 GET 节点和只读 MCP；教师工作台真实协议探针已通过，但两套 Agent 均未完成接入。CC 缺 Bearer 凭据支持，原版缺写工具审批/账本，两边需证书信任。

### 第八课 可复用 Agent

[Lesson 08](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-08)把可复用 Agent 的能力与节点处的任务分开：已有 Agent 可被多个工作流引用，也可先建临时 Agent 再保存。节点传入任务、上下文并取回输出。Hify 当前是 Agent 绑定 Workflow，反向 Agent 节点尚无；`ChildAgentTask` 协议不是 worker。若实现，需版本固定、递归/深度限制、共享预算、状态关联及知识门禁，不能只调用一个模型就声称完整 Agent 复用。

### 第九课 模板排版

[Lesson 09](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-09)让 Agent 负责内容，Template 负责固定布局，演示变量映射和 Jinja。Hify TEMPLATE 已有固定文本插值，但不是 Jinja 解释器；它不支持任意模板循环与过滤器。优先保持可预测和无代码执行的简单语义，增加数据类型后再考虑有界列表格式化。

### 第十课 发布和监控

[Lesson 10](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-10)把发布更新、Web/API/MCP 等访问点、CSV 批量执行、工作流作为工具和运行监控连接起来。Hify 已有版本、Run/事件及节点详情，但没有独立用户 WebApp、应用 API Key、批量导入或按版本趋势分析。当前后台入口不是经过访问控制的公开应用；新增对外发布必须带认证与预算设计。

## Simple Chatbot 与新版 Agent

[Simple Chatbot](https://docs.dify.ai/en/learn/tutorials/simple-chatbot)使用 LLM 结构化字段、Code 节点和 Answer 模板，核心是机器可消费的输出及节点间类型衔接。Hify 没有代码沙箱，不能把任意 Python/JavaScript 放进应用进程。本轮考虑受限 JSON 输出校验和确定性转换，沙箱执行留作独立安全项目。

[Introducing New Agent](https://dify.ai/zh/blog/introducing-new-dify-agent)发布于 2026-08-27：Agent 成为可独立维护、发布与复用的资源；配置与对话构建分开，构建草稿先预览；访问点和追踪说明谁在使用。工具、技能与临时沙箱命令承担不同职责。两个重要范围限制：集中式 Skill Management 在文中仍是后续计划；按月日志归档明确不提供给 Community Edition。Hify 可借鉴变更说明、引用关系和按版本观测，不把市场公告当本地能力验收。

## 固定基线下的实现差距

下表是源码判断，不代表本轮已经测试或上线。CC 列结合此前双方源码复核，新增代码另行验收。

| 能力 | 原版 Hify | hify-cc | 本轮处置 |
| --- | --- | --- | --- |
| Agent 不可变发布版本 | 已有；会话固定版本 | 基线无，读当前配置 | CC负责人补版本；原版保留兼容 |
| 持久 Run 和事件重放 | 已有，终态与恢复仍有开放边界 | POST SSE，缺 durable Run | 不以日志数量比较可靠性 |
| Workflow LLM 与外部请求 | 本地新增，HTTP P1未关闭 | 已有 LLM/API_CALL | 原版先修P1并真实验收 |
| 结构化输入表单 | 单条userMessage | 基线单条input | 原版优先补有界输入schema |
| 结构化输出/提取/汇合 | 无专门节点 | 基线无完整对应体系 | 候选；先类型校验再扩节点 |
| 循环与并行子图 | 无 | 无完整子图迭代 | 不本轮仓促实现任意调度 |
| 语义知识检索 | 本地真实embedding，小库精确扫描 | 真实embedding、父子分块及可选rerank | 各自独立质量/部署证据 |
| 知识源交付核验 | Chat有，Workflow组合不等价 | 无同等交付前原文门禁 | 明确输出边界 |
| Agent作为Workflow节点 | 无，child协议无worker | 基线无 | CC独立切片；原版待设计 |
| 可复用Skills | 无 | 基线无 | 只读指令包可评估，脚本不执行 |
| MCP Bearer与TLS | 支持加密Token，缺endpoint专属CA配置 | 基线无Bearer字段 | 不降低TLS/风险门禁换连通 |
| MCP写工具 | 不开放，缺精确审批与账本 | HIGH需人工确认 | 全权限授权不等于技术能力完成 |
| DSL导入导出 | 无专用入口 | 有JSON编辑，不等于可迁移导出 | 候选；不导出服务端快照/凭据 |
| 监控与反馈 | Run事件/节点记录，缺运营趋势 | OTel与反馈，缺不可变版本维度 | CC负责人补，原版独立评估 |
| 外部访问控制 | /hify无登录 | 公网nginx Basic Auth但HTTP | 写能力上线前独立核查暴露面 |

原版证据入口：`backend/hify-workflow/.../application/WorkflowEngine.java` 的节点switch及执行持久化；`WorkflowExecutionContext.java` 的变量空间；`WorkflowExternalNodes.java` 的快照与配置约束；`WorkflowHttpClient.java` 的出站策略；`backend/hify-chat/.../application/RunApplicationService.java` 的绑定执行与Chat门禁；`backend/hify-agent/.../AgentServiceImpl.java` 的发布；`backend/hify-mcp/.../McpCapabilityService.java` 的READ限制。CC凭据边界见 `hify-mcp/.../dto/McpServerSaveReq.java` 和 `client/McpToolClient.java`。

## 本轮交付选择

1. 先完成 DIFY-AUDIT-001 与 WORKFLOW-NODES-002。原版外部节点旧门禁通过只证明当时的测试；独立发现的安全漏洞仍阻塞发布。
2. 再完成 WORKFLOW-INPUTS-001，以官方课2的“客户姓名加正文”作为真实可用闭环，不只是JSON字段存在。
3. 结构化输出、分支汇合、导入导出、Agent访问点等按剩余窗口和回归成本另开原子任务；不让未验收实验进入发布包。
4. 发布必须固定源码和产物身份、显式门禁、备份、健康/迁移检查、真实正反用例以及访问链接。应用改进数量不是验收替代品。

本轮明确不做：完整Dify插件生态、商业多租户/计费、任意命令沙箱、无限Agent递归或无边界并行。教师工作台的完整权限授权已收到，但其写能力接入仍需审批与账本工程，不通过伪造只读标记实现。

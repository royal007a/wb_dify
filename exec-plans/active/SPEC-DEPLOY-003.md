# SPEC-DEPLOY-003：安装器故障收尾与成功边界

基线 4eff833。只改工作区脚本、隔离夹具和证据，不连接132、不启动真实服务、不读取真实凭据。

## 验收与步骤

1. 先加能在旧代码上失败的用例：sh/dash 下 stderr 关闭，迟到工作仍恢复旧服务；健康失败仍停止新服务并保持原退出码1。
2. 预检健康次数0/000/301及缺失jar/index/snippet/key均在任何systemctl之前失败。避免POSIX AND列表绕过set -e。
3. 在成功后的诊断sha处用假命令阻塞，分别发送HUP/INT/TERM；已健康的新服务、新静态文件和snippet不回退。信号可以中断诊断，本任务不保证诊断完成。
4. on_exit先捕获退出码，再set +e；必要服务动作优先，诊断失败不得阻止恢复或覆盖原失败码。最后实际健康/元数据检查后解除trap，再输出诊断。
5. 运行部署窄测与harness门禁；代码先提交，证据后提交，交mymacclaude只读复验。复验前禁用此脚本的新发布。

## 边界

不承诺SIGKILL、清理期间第二次信号、systemctl自身失败下的服务恢复；不自动恢复数据库或静态文件；假命令不证明真实SSH/systemd行为。smoke异常ID、schema目标和索引任务准入仍归SPEC-DEPLOY-004。

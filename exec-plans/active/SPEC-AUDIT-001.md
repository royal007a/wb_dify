# 全功能验收规格与漂移门禁

## 目标与边界

用户要求基于参考资料审查原版 Hify、补齐接口/功能测试规格、验证、修复并重新部署，由 mymacclaude 独立 review。任务状态只看 harness/tasks.json。
本原子任务仅建立完整可核对规格与基线，后续 SPEC-VERIFY-001 负责全部行为验证/修复，SPEC-DEPLOY-001 负责部署。不得把本任务完成解释为总目标完成。

## 步骤

1. 从 Controller、前端页面、运行状态机与现有测试提取清单；区别课程建议、现有实现、有意非目标。
2. 固化 docs/spec/ API 清单和功能测试矩阵；Spring 实际路由与规格集合逐项双向比对。
3. 为已有测试映射记录源码位置、验收断言、未覆盖路径；新鲜测试结果另存 evidence。
4. 修正文档过时能力描述，不自行增加非目标；所有真正缺陷在后续原子任务加红灯回归。
5. 在隔离测试环境运行后端与 Harness 门禁，提交规格，交独立 reviewer 抽查。

## 安全与验收

- hify-cc 始终只读；不打印环境变量、凭据或用户消息；远端只读核验，不对存量业务做破坏性测试。
- endpoint 清单完整不代表行为全覆盖；测试方法存在不代表此次已执行。必须明确标注。
- Docker PostgreSQL 与浏览器端到端作为后续独立门禁，不以 H2/Mock 代替真实依赖。
- 新模型/SSO/计费/分布式执行不因文档审计而自动纳入；需要用户授权的扩展列差距。

# WORKFLOW-AGGREGATION-001

授权：2026-10-05 三小时完善目标；先设计和计划，交叉 review 后实现。机器状态只看 tasks.json。

## 范围与理由

基线 7ddff72。工作流当前是单路径解释器，普通模板只能引用必经上游，两个互斥分支不能把不同名称的结果交给同一个下游节点。新增受约束的 AGGREGATOR，保留串行解释器和普通模板安全规则。不新增依赖、迁移、外部服务或工具权限。

设计依据：[Dify 第5课](https://docs.dify.ai/en/learn/tutorials/workflow-101/lesson-05) 的互斥分支汇合。不是并行 join，也不是任意 DAG 调度。官方文档阅读日期 2026-10-05，不据此承诺社区版版本对等。

## DSL 与静态规则（待 review）

- 配置 `{ "candidates": ["branchA.result", "branchB.result"], "outputVariable": "result" }`；候选2–16项，必须是唯一的 `node.variable`，不支持自由模板或默认回退。
- 所有候选必须来自严格祖先且输出变量确实已声明；同一个生产者不可列两次。候选生产者可以是 START 的具名输入，但其运行值仍须存在。
- 对到达聚合节点的每一条结构路径，恰好经过一个候选生产者。利用无环图的拓扑序传播候选计数集合，计数截到2（表示多于一个），要求到达聚合的集合仅为 `{1}`。不枚举指数级路径。
- 只在 AGGREGATOR 的 candidates 字段允许非必经祖先。普通 TEMPLATE、LLM、END 等的 dominator 验证原样保留；聚合后的下游引用聚合输出，仍需必经。
- 条件表达式不做可满足性求解：结构上有歧义即拒绝，哪怕用户认为某条路径实际不可达。

## 运行与兼容

- 从当前上下文按键存在性选候选，而不是 truthiness；0、false、空文本不是缺失。必须恰好一个存在且非 null 的候选，才复制值到新的输出键；不字符串化、不覆盖已有变量。
- 聚合只是一个普通串行节点，沿用50步、父 deadline/cancel 和节点运行记录；不执行未选分支。非法/被篡改发布图仍在写 run 行之前拒绝。
- 不给旧DSL补字段、不重新序列化旧版本；原始dslJson SHA与Agent固定checksum规则不动。新候选天然包含在新发布DSL中。
- 这一切片只保证变量选择，不把知识引用或模型输出变成 VERIFIED evidence。
